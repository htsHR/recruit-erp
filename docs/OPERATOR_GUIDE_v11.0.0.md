# Recruit ERP v11.0.0 운영자 설명서

이 문서는 실제 채용 업무를 시작하고 끝낼 때 운영자가 따라야 할 최소 절차입니다. 화면 확인과 훈련에는 실제 개인정보가 아닌 가상 자료를 사용합니다.

## 업무 시작

1. 운영 홈페이지 주소와 화면 버전 `v11.0.0`을 확인합니다.
2. 본인 계정으로 로그인하고 상단의 권한이 업무 역할과 맞는지 확인합니다.
3. 클라우드 상태가 정상인지, 저장·삭제 대기 또는 충돌 확인이 남아 있지 않은지 확인합니다.
4. `운영 준비 점검`에서 자동 안전 점검에 빨간 항목이 없는지 확인합니다.
5. `오늘 할 일`에서 면접, 연락, 결과 입력, 입사와 출근 확인 대상을 확인합니다.

## 업무 중

- 저장 실패 안내가 나오면 화면을 닫거나 새로고침하지 말고 입력 내용을 별도로 보관한 뒤 저장공간과 브라우저 설정을 확인합니다.
- 삭제 대기가 남으면 같은 사람을 다시 등록하지 말고 인터넷 연결 후 재시도합니다.
- 동기화 충돌은 두 값을 비교한 뒤 사용할 쪽을 직접 선택합니다.
- 조회 전용 사용자는 수정·삭제·복원·민감정보 내보내기를 시도하지 않습니다.
- 지원자를 사원으로 바꿀 때 사번 중복과 필수 서류, 출근 확인을 먼저 확인합니다.
- 화면을 떠날 때는 개인정보 화면 잠금을 사용합니다.

## 백업

1. 중요한 일괄 수정·Import·복원 전에는 백업센터에서 암호화 전체 백업을 만듭니다.
2. 파일 확장자가 `.erpbackup`인지 확인합니다.
3. 백업 파일과 비밀번호를 서로 다른 회사 승인 위치에 보관합니다.
4. 평문 JSON은 호환이 꼭 필요한 경우에만 관리자 고급 메뉴에서 사용합니다.
5. 실제 운영 백업을 메신저, 개인 이메일, GitHub, 테스트 artifact에 올리지 않습니다.

## 업무 종료

1. 저장·삭제 대기와 동기화 충돌이 0건인지 확인합니다.
2. 당일 변경 이력에 이상한 대량 수정·삭제·내보내기가 없는지 확인합니다.
3. 회사 기준에 맞는 암호화 백업이 생성됐는지 확인합니다.
4. 공용 컴퓨터라면 로그아웃하고 화면을 잠급니다.
5. 운영 준비 점검의 수동 확인은 실제로 훈련한 항목만 체크합니다.

## 정기 점검

- 매주: 관리자·채용담당자·조회전용 계정으로 대표 작업의 허용·차단을 확인합니다.
- 매월: 가상 자료로 암호화 복원과 삭제 재생성 방지 훈련을 실시합니다.
- 릴리스 전: GitHub Actions, Vercel Preview, Supabase RLS와 Security Advisor를 확인합니다.
- 담당자 변경 시: 사용자 권한, 백업 비밀번호 보관 책임, 장애 연락 순서를 인수인계합니다.

## 제한

브라우저 자동 점검만으로 실제 계정의 Supabase RLS, 다른 PC의 삭제 동기화, 외부 백업 파일의 보관 상태를 증명할 수 없습니다. 이 항목은 운영자가 가상 자료로 직접 확인해야 합니다.

Supabase Free 요금제 사용으로 Leaked Password Protection은 미사용.
해당 제한을 인지한 상태로 운영한다.

운영 준비 화면에서는 이 항목을 `알려진 요금제 제한`으로 표시하며, 그 자체만으로 READY를 차단하지 않습니다. RLS·감사로그·권한 상승·공개 `SECURITY DEFINER` RPC 차단 검증은 계속 필수입니다.
