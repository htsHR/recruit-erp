# v10.61.0 저장소·속도 운영 안내

## 무엇이 바뀌었나요?

ERP의 큰 데이터 여섯 종류를 기존 localStorage에 정상 저장한 뒤 IndexedDB에도 안전 복사합니다.

1. 지원자
2. 사원
3. 협력학교
4. 일정
5. 입사대기자
6. 안내문 템플릿

기존 화면은 동기식 localStorage 데이터를 계속 사용하므로 등록, 수정, 삭제, 클라우드 동기화 방식은 바뀌지 않습니다. IndexedDB 안전 복사가 실패해도 이미 저장된 원본을 자동으로 지우거나 바꾸지 않습니다.

## 저장소·속도 화면

시스템 메뉴의 `저장소·속도`는 관리자 또는 로컬 관리자만 사용할 수 있습니다.

- `사용량 다시 확인`: 브라우저가 제공하는 최신 사용량 추정치를 다시 읽습니다.
- `안전 복사 갱신`: 여섯 데이터의 안전 검사를 거친 뒤 IndexedDB 복사를 갱신합니다.
- `안전 스냅샷 만들기`: 현재 상태를 별도 스냅샷으로 보관합니다. 최대 5개이며 오래된 항목부터 자동 정리됩니다.

화면에는 데이터 내용이 아닌 건수, 용량, 시각만 표시됩니다.

## 경고가 보이면

1. 백업센터에서 암호화 전체 백업을 내려받습니다.
2. 다운로드 파일이 `.erpbackup`인지 확인합니다.
3. 불필요한 다른 사이트의 브라우저 데이터나 오래된 다운로드를 정리합니다.
4. ERP의 `사용량 다시 확인`을 누릅니다.

브라우저 저장공간을 정리할 때 이 사이트의 데이터까지 삭제하면 localStorage와 IndexedDB가 함께 사라질 수 있습니다. 먼저 외부 암호화 백업을 만들어야 합니다.

## 성능 기준

자동 검사는 실제 개인정보가 아닌 가상 데이터만 사용합니다.

- 지원자 5,000명
- 사원 1,000명
- 학교 500개
- 합계 6,500건의 건수와 UTF-8 용량 요약을 3초 이내에 완료
- 기존 목록 페이지 나눔 유지
- 390×844 모바일과 1366×768 125% 확대에서 가로 화면 넘침 없음

## 남은 제한

- IndexedDB는 같은 브라우저 안의 보조 안전 계층이며 외부 재해 복구 백업이 아닙니다.
- localStorage의 브라우저별 실제 한도는 브라우저와 기기 설정에 따라 달라집니다. 4MB 경고는 보수적인 운영 기준입니다.
- `navigator.storage.estimate()` 값은 브라우저 추정치이며 정확한 예약 용량을 보장하지 않습니다.
- 현재 데이터의 단일 원본을 IndexedDB로 완전히 전환하려면 앱 시작, 클라우드 병합, 복원 절차를 모두 비동기로 바꾸는 별도 검증이 필요합니다.
