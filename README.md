# Recruit ERP

[![ERP 자동 검사](https://github.com/htsHR/recruit-erp/actions/workflows/quality-checks.yml/badge.svg?branch=main)](https://github.com/htsHR/recruit-erp/actions/workflows/quality-checks.yml)

채용 지원자, 일정, 사원명부와 협력학교를 관리하는 웹 ERP입니다. 현재 운영 버전은 **v10.58.0**입니다.

운영 홈페이지: https://recruit-erp.vercel.app

## 매일 사용할 때

1. 화면 왼쪽 아래에서 클라우드 상태를 확인합니다.
2. `동기화 정상`이면 평소처럼 사용합니다.
3. `저장 대기` 또는 `삭제 대기`가 보이면 인터넷 연결 후 `다시 시도`를 누릅니다.
4. `삭제 대기 확인`에서 아직 클라우드에 반영되지 않은 삭제 요청을 확인할 수 있습니다.
5. `충돌 확인`이 보이면 두 자료를 비교하여 사용할 정보를 선택합니다.
6. 중요한 대량 수정 전에는 `백업/내보내기`에서 전체 JSON 백업을 받습니다.

## 자료를 안전하게 다루는 규칙

- 실제 지원자·사원 정보는 테스트에 사용하지 않습니다.
- 업데이트 검사는 `테스트지원자`처럼 만든 가상 자료만 사용합니다.
- JSON Import 전에는 변경 미리보기를 확인합니다.
- CSV 파일을 열었을 때 수식처럼 실행될 수 있는 값은 자동으로 일반 문자 처리됩니다.
- 공용 컴퓨터에서는 사용 후 로그아웃하고 개인정보 화면 잠금을 사용합니다.
- `<img ...>` 같은 문자열이 이름이나 메모에 들어와도 프로그램으로 실행되지 않고 글자로만 표시됩니다.
- 출처가 불분명하거나 ID 검사에 실패한 JSON 파일은 가져오지 않습니다.

## 업데이트 자동 검사

GitHub에 변경 요청이 올라오거나 `main`에 코드가 합쳐지면 다음 항목을 자동 검사합니다.

- 브라우저 저장 실패 안전장치
- 사원 JSON Import의 빈값 보호와 변경 미리보기
- 모든 CSV 내보내기의 수식 실행 방어
- 개인정보 화면 잠금과 내보내기 기록
- 클라우드 충돌 감지와 전송 재시도 대기열
- 클라우드 삭제 대기·실패 재시도·화면 재등장 방지
- 인라인 실행 속성 차단, JSON/ID 검사와 CSP 보안 정책
- 외부 Supabase 라이브러리 버전·무결성 고정
- 관리자·채용담당자·조회전용 역할표와 주요 저장 경로 권한 검사
- 조회 전용 수정·삭제 차단과 Supabase RLS 정책 파일
- 전체 JavaScript 문법
- 화면·프로그램·변경 기록의 버전 일치
- Vercel 보안 응답 설정

개발 컴퓨터에서 같은 검사를 실행하려면 Node.js 20 이상에서 아래 명령을 사용합니다.

```text
npm run check
```

## 안전한 업데이트 순서

1. `agent/...` 작업 브랜치에서 수정합니다.
2. 가상 데이터로 `npm run check`를 통과시킵니다.
3. GitHub 변경 요청에서 자동 검사와 Vercel 미리보기를 확인합니다.
4. 문제가 없을 때만 `main`에 병합합니다.
5. 운영 홈페이지의 화면 버전과 주요 기능을 확인합니다.

## v10.58.0 변경 이력 설치

`supabase/migrations/20260802094828_audit_history_v10_58_0.sql`을 Supabase SQL Editor에서 한 번 실행해야 합니다.

- 지원자·사원·협력학교·일정의 등록·수정·삭제 기록
- 삭제 사유, 백업 복원, 내보내기, 사용자 권한 변경 기록
- 관리자 전용 변경 이력 화면과 Supabase RLS
- 주민등록번호·연락처·이메일·주소·급여·메모 등 민감값 원문 미기록
- 오프라인 기록 보관 및 연결 후 자동 재시도

자세한 변경 내역은 `CHANGELOG_v10.58.0.md`를 확인하세요.

## v10.57.0 사용자 권한 설치

화면 코드 배포만으로는 서버 권한이 완성되지 않습니다. Supabase 프로젝트의 SQL Editor에서
`supabase_migration_v10.57.0_rbac_rls.sql`을 한 번 실행해야 합니다.

1. SQL 실행 결과에서 가장 먼저 만든 Auth 계정이 `admin`인지 확인합니다.
2. ERP에 관리자로 로그인합니다.
3. `시스템 → 사용자 권한`에서 다른 계정을 `채용담당자` 또는 `조회 전용`으로 지정합니다.
4. 조회 전용 테스트 계정으로 로그인하여 수정·삭제·복원 요청이 거부되는지 확인합니다.

서버 SQL을 적용하기 전에는 ERP에 `Supabase 권한 SQL 적용 필요` 경고가 표시됩니다.

## 문제가 생겼을 때

- 화면 버전이 예전이면 `Ctrl + F5`로 새로고침합니다.
- 저장 실패 메시지가 나오면 화면을 닫거나 초기화하지 말고 먼저 JSON 백업을 받습니다.
- 동기화 실패 시 로컬 자료와 저장·삭제 요청은 유지되며, 인터넷 복구 후 다시 시도할 수 있습니다.
- 새 버전에서 큰 문제가 생기면 GitHub의 직전 정상 병합 커밋으로 Vercel을 되돌립니다.
- 백업 복원은 반드시 미리보기와 가상 데이터 검증 후 진행합니다.

## 알려진 제한

- 처음 v10.53 이상을 실행하는 브라우저에는 과거 동기화 기준점이 없습니다.
- 삭제 요청을 취소하면 서버에 남아 있던 자료가 다음 동기화에서 다시 나타날 수 있습니다.
- Supabase 권한 SQL을 적용하지 않은 프로젝트에서는 서버 역할 분리가 작동하지 않습니다.
- 로컬 전용 모드는 Supabase 계정 권한과 별개이며, 그 브라우저 안의 데이터만 관리합니다.
- CSP는 인라인 JavaScript를 차단하므로 새 화면 버튼도 중앙 이벤트 방식으로 연결해야 합니다.

버전별 상세 내용은 저장소의 `CHANGELOG_v*.md` 파일에서 확인할 수 있습니다.
